# スマホ横ずれの再現と修正

確認日：2026-09-14。修正前：`4da5fba`（PR #26統合後のmain）。修正対象：`7abe5f4c7c91e315e985325b4bd080d94ac251f8`。対応：[WAR-013](../BACKLOG.md#war-013)。隔離ブラウザと合成データのみを使用した。

## 原因と修正前の測定

ChromiumとWebKitのモバイル構成で、トップの回転した装飾が本文から2pxはみ出していた。本文には縦スクロールだけを指定していたが、横方向も計算上 `auto` になり、本文単独で横スクロールできた。ルート幅だけを調べる既存の検査では見つからなかった。

| 対象                                        | 修正前        | 修正後       |
| ------------------------------------------- | ------------- | ------------ |
| 320px幅の本文：表示幅／スクロール幅         | 288px／290px  | 288px／288px |
| 390px幅の本文：表示幅／スクロール幅         | 358px／360px  | 358px／358px |
| 本文の横スクロール位置（右へ100pxの要求後） | 2px           | 0px          |
| リフレッシュボタンの押下時の位置            | y=12px → 15px | y=12pxで不変 |

ボタンの移動はTailwindの1px移動と共通CSSの2px移動が重なったもの。横ずれとは別の動きだが、ユーザーの「カチッと固定」という指示に合わせてモバイルでは両方を抑えた。

## 修正

- 回転した装飾を8px内側へ動かし、はみ出しそのものを解消。
- 1024px未満の本文で横スクロールを非表示・横方向のoverscrollを抑制。ルートも横方向をclipする。
- 押下・ホバーによる部品の位置移動を1024px以上に限定。モバイルの押下反応は色と影で示す。
- 縦スクロール、拡大を許すviewport設定、ダイアログの静的な中央配置は維持。保存処理・台帳・下書きは変更なし。

## 検証

- `pnpm check`：成功（静的検査、未使用コード、型、単体35件、本番ビルド）。
- `pnpm test:e2e --workers=3 --output=artifacts/stability-e2e`：全131件成功、対象外1件、失敗0件。対象外は既存のスマホ専用検査のPC実行。登録・編集・精算・保存・復旧・axe検査を含む。
- `layout-stability.spec.ts`：6件成功。モバイルは320・375・390・430・640・844・1023px幅、PCは1024・1440px幅で主要3画面の本文・ルート幅を検査。844px幅では高さ390pxの横向き構成を使用。
- ChromiumではCDPのタッチスワイプで横移動0と縦スクロールを確認。WebKitのPlaywrightではスワイプ・モバイルwheelが提供されないため、スクロールAPIで確認した。両者を実機操作の証明としない。
- 両モバイル構成でボタン・候補アイコンを押下し、旧150msトランジションをまたぐ250msの間、位置・大きさが不変であることを検査。
- 確認画面の開閉を繰り返し、本文・ヘッダーの位置、画面内への収まり、キャンセルへの初期フォーカスと起点への復帰を確認。
- 390px幅のWebKit画面を目視確認。装飾が切れず、従来の右寄せ操作とポップな配色を保持。

実機iPhone/Androidのバウンス・慣性・ソフトキーボード・ピンチ拡大、本番操作の確認は含まない。引き続きWAR-005・006で扱う。
